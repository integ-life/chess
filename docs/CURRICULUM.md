# 中国象棋完整学习体系

## 目标

课程从规则和记谱开始，经过基本杀法、战术、开局、中局与残局，最终训练学习者独立计算、实战和复盘。产品内权威目录在 `frontend/src/course/curriculum.ts`，当前共 8 个阶段、86 课。

产品总纲逐项核对实际开放课程标题，并以自动化测试防止目录与课程内容再次漂移。除第一阶段无需先修外，每一阶段都以上一阶段的“通过标准”为建议起点；学习者未达到标准时，可以先回到上一阶段的迁移题和延迟复习卡补强。

## 每课学习闭环

1. 用自己的语言解释基本概念和规则边界。
2. 在棋盘上逐着展示结构、计划和合法变化。
3. 比较主线与其他选择，说明“不这样走”的具体代价。
4. 完成两至三道局面题和一项概念检查。
5. 从本地 canonical games 或标准局面中复盘实例。
6. 次日和七日后重新完成关键题，避免只形成短期熟悉感。

课程页现已把第 6 步落实为离线优先复习卡：达到各课的完成条件后才能安排计划，随后记录本课、次日和七日三次主动回忆。记录先写入当前设备，登录状态下与棋谱、推演一起同步到账号；换设备登录后会恢复，离线修改在联网后按最后更新时间合并。旧版 localStorage 记录会在首次打开对应课程时自动迁移。

第一阶段八节规则课另提供具体规则判例：学生先对双方路数、炮架、兵卒、应将、将帅照面、记谱和重复状态作出判断，再展开答案核对规则边界。判例复用本课棋盘与推演入口，不另建一套脱离规则内核的诊断系统。

判例问题与答案分开呈现：学生先写结论和适用规则，再主动展开依据；次日与七日复习还要求补一个反例。课程概览分别统计八道判例和八道检查题，避免把展开阅读当成已经完成独立判断。

八节规则课的棋盘预测、规则判例、概念检查与 40 道延迟复习题已统一抽离到 `frontend/src/course/exercises/foundation.ts`，每课 3 道即时题和 5 道复习题，共 64 道练习；课程正文只组合对应练习，页面交互保持不变。即时反馈继续说明相关规则、成立条件和遗漏步骤；复习题再要求画出控制点、保存 FEN、枚举合法着、写出反例，并用镜像视角或完整合法性流水线复判。测试锁定四类练习与课程一一对应，并要求每条选择反馈和复习题都不少于 55 个字符；答题结果仍通过礼貌播报提供给读屏用户。

本轮直接核对本地 WXF《Introduction to Chinese Chess》规则与棋子章节，并通过 `backend/qipu-sources/opening-materials/SHA256SUMS` 验证教材快照；课程页不再把仅用于开局研究的 Wikibooks 快照误写成规则来源。规则结论继续以 TypeScript / Go 双内核和共享 perft 为执行依据。

末课“合法着、重复与胜负”把循环判断拆成可执行步骤：先比较棋子摆放与行棋方，再截取两次同一局面之间的完整着法，逐着标记将军、追捉目标、被迫应对和普通变位，最后比较双方责任。该原则核对自本地 WXF 入门草案第 12-13 页，快照 SHA-256 为 `bae133202d70f89e`；由于资料明确是初稿且未覆盖全部残局裁决，课程不写通用固定次数，正式结果以比赛采用规则为准。当前 TypeScript / Go 内核只判合法着、将死与困毙，不自动裁决重复、长将或长捉。

## 内容审查门槛

- 规则内容必须与 TypeScript/Go 规则内核和测试一致。
- 同一课内的讲解标题、概念、检查清单和判断要点不得重复；目录同步不能代替正文内容审查。
- 所有走法、例局和练习必须合法回放。
- 经验原则必须标明适用条件，不能伪装成绝对规则或引擎结论。
- 社区资料保留来源、许可或使用边界；产品正文独立表达，不复制第三方全文。
- 每轮执行内容审查、移动端交互检查、测试和生产构建；可靠后再提交部署。

资源页分别列出 canonical 棋谱数据源与八项课程资料源，并保留公开原始链接、本地快照文件名、SHA-256 前缀和使用边界；原始 PDF / HTML 仍只在本地研究目录保存，不随前端发布。课程路线与 86 节课不再提供来源跳转，学习过程只保留必要的来源名称和 canonical ID。

所有绑定社区棋谱的课程来源卡继续显示完整 canonical ID 与来源库，但不再链接第三方页面。主例局、迁移例局和十二盘开局代表局的 `sourceUrl` 仍保存在版本化数据与本地 SQLite provenance 中，可在资料审查时反查；ID 只作来源身份，不代表质量评分。

开局代表局和复盘完整棋谱的推演入口统一使用 `canonical-<ID>`，不再生成 `course-example-*` 或 `practice-*` 课程别名。公共棋谱注册表按 ID 去重，并让课程版完整着法覆盖同 ID 的目录快照，避免同一棋局出现两套前端身份。

杀法、战术、中局判断、中局计划、残局与复盘六类棋谱课的 330 个主线位置和 56 个迁移位置现在共生成 703 条具体候选说明。学生选中非社区主线后，页面会说明实际棋子的 ICCS 起止点、落点区域、线路或控制变化、吃子与开车路事实，再并列主线目的和偏离时需要检查的风险；同一规则感知函数也供开局变招复用。测试固定位置数、说明数、最低细节和同局面候选不重复，仍不把合法偏离判成 Pikafish 劣着。

六类棋谱课自身的 330 组“主线目的 / 偏离风险”也设有正文门槛。审查只扩写了 38 组中的 44 段不足 18 个字符的薄弱说明，集中补清杀法中的逃点、应将与炮架，战术中的目标保护与连续先手，以及三条中局计划的增援时机；其余 292 组保留原文。测试要求全部 660 段均达到最低细节，避免候选着说明具体、课程结论却只剩一句标签。

## 开局体系例局

第四阶段为十二个开局主题各绑定一盘来自本地东萍或 WXF canonical dataset 的完整代表局，覆盖中炮、屏风马、过河车、五七炮、单提马、顺列炮、仙人指路、飞相和过宫炮等体系。课程先用合法教学主线讲结构，再在完整实战中自动寻找第一个不同着；若代表局完整走完教学主线，则标出主线后的第一步实战延伸。页面比较实际计划与被推迟任务，不把合法走序差异冒充 Pikafish 优劣；测试逐着验证十二盘完整棋局、来源 URL 和分叉或延伸点。

十二课各自提供三项“脱谱后重新排任务”检查：先识别对手的新威胁，再检查原计划仍未完成且仍适用的任务，最后用兵形接触、中心打开、强制交换或主战场确定等信号决定何时停止背谱并进入中局重评。每课另有五道逐课延迟复习题，要求重建判断方法、复算局面题、分析完整代表局、迁移到个人棋谱并在次日或七日复查；只提供按结构应变的判断框架，不把未经引擎验证的走法写成唯一答案。

每课两道局面题的检查点已与概念题一起抽离到 `frontend/src/opening/exercises.ts`；每课固定一题红方走、一题黑方走。显示合法选项前，先要求学生写出至少两着候选、各自的对手回应，以及每着完成或推迟的开局任务；切换题目后重新隐藏选项。社区主线只用于核对计划与走序，不把未被选择的合法着判成引擎劣着。

十二课共 114 条教学主线注释均按“这步改变了什么、完成哪项任务、下一步要检查什么”扩写，不再用“自然出马”“快速出车”一类标签代替逐着讲解。测试要求每条注释至少 25 个字符，并继续逐着通过规则内核验证。

每一步的两条教学变招也不再只按“马、炮、车”给出同一段泛化反馈。页面会写明棋子实际的 ICCS 起止点、落在左翼/中路/右翼、改变的控制或线路、是否开车路或吃子，再说明主线棋子因此被改点或推迟的任务；共 228 条变招说明由同一规则感知函数生成并逐条测试为合法、足量且同局面互不相同。它们仍是计划比较，不冒充 Pikafish 排名。

十二节开局课的 12 道概念题、24 道局面题与 60 道延迟复习题均独立保存在 `frontend/src/opening/exercises.ts`。36 个概念选项反馈把答案还原为结构判断；五道复习题再分别要求记录 FEN、候选着、最强回应、参战子、车马炮线路、结构转换与停止背谱信号。测试锁定十二课映射、每课红黑双边检查点、唯一正确项与五道互异复习题，并要求概念反馈不少于 65 个字符、复习题不少于 55 个字符。
