# 中国象棋课程剩余工作

更新时间：2026-08-10

## 当前基线

- 8 个阶段、86 课均已有正式页面和课程内容。
- 每课 5 道独立延迟练习，共 430 道。
- 课程复习进度已改为离线优先并随账号跨设备同步。
- 课程例局、迁移局面和代表局由自动化测试执行合法回放。

## 尚未完成

### 1. 引擎级课程验证

- 为关键局面批量生成可复现的 Pikafish MultiPV 数据。
- 分开保存引擎分数、社区实战频率和教学推荐，避免混成单一结论。
- 加入有明确证据的错误着、最佳回应和分差，并对异常结果人工复核。
- 优先覆盖开局分叉、中局候选计划、战术最强兼应和残局关键边界。

### 2. 残局完整胜和证明

- 将目前用于教学的部分五着片段扩为完整变化树。
- 补充守方最强抵抗、不同先后手、将位、兵位和子力交换后的边界局面。
- 评估引入残局库或深度引擎验证；没有完整证据时继续保留“教学线索、非完整证明”的声明。

### 3. 赛事级重复、长将与长捉裁决

- TypeScript 与 Go 规则内核目前只自动处理合法着、将军、将死和困毙。
- 后续需要保存完整局面历史，逐着识别将军、追捉目标、被迫应对和责任方。
- 裁决必须绑定明确采用的比赛规则，不实现成通用的固定次数重复判和。
- 完成后补共享 fixtures、前后端一致性测试和课程判例。

### 4. 学习评估与个性化

- 为各阶段加入与“通过标准”对应的正式测评，而不只依赖完成复习勾选。
- 增加错题记录、重做队列、逾期复习和薄弱主题统计。
- 根据答题与复习表现推荐补课、迁移题和下一阶段，而不是只按固定目录前进。

### 5. 教学内容继续深化

- 杀法：补齐守方逃将、吃子、垫子、拆炮架和塞马腿的完整资源树。
- 战术：验证最强兼应、拒绝和反先，不只比较社区主线。
- 开局：补常见转置、样本频率与脱谱后的真实候选排序。
- 中局：为计划比较补充更具体的到达速度、交换结果和停止条件证据。
- 实战复盘：逐步加入真实学习者棋局作业和经过审查的示范批注。

### 6. 真实学习者验证

- 邀请不同水平学习者走完规则、杀法和至少一个开局单元。
- 记录看不懂的术语、过长课节、误导性选项、移动端操作阻力和复习流失点。
- 用完成率、次日/七日正确率和迁移题表现调整难度曲线，再决定是否扩充课程数量。

## 实施顺序建议

1. 引擎级关键局面验证。
2. 残局完整证明与边界题。
3. 阶段测评、错题与个性化复习。
4. 赛事级循环裁决。
5. 持续真实用户测试和内容深化。

每轮用户可见改动必须同步更新 `frontend/src/changelog.ts`；涉及棋谱和裁决的改动必须完成前后端规则测试、合法回放、生产构建与移动端交互检查。
