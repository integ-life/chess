# 中国象棋开局基础课程设计

## 目标与范围

先做一套面向“会走棋，但没有系统开局框架”的 12 课基础课程。目标不是背完 ECCO，而是让学习者能够：

1. 用出子、车路、河界、将帅安全和子力协调解释一个开局着法。
2. 识别五个 ECCO 大类及常见转置。
3. 为红方建立一套主动选择，为黑方准备对中炮和非中炮的基本应对。
4. 在离开背诵线路后，仍能用原则选择合理着法。

每课只教一个核心判断、一个基本阵型和 2-3 个关键选择点。主线控制在 6-10 回合；更深变化从现有棋谱和局面图按需展开，不写死进课程正文。

## 课程结构

### 第一单元：先会判断，不先背谱

| 课 | 主题 | 核心判断 | 练习 |
| --- | --- | --- | --- |

## 每课统一教学循环

1. **概念讲解**：两段导读、三段深度讲解、四个术语定义和三个上棋盘前检查问题；学习者主动确认后才显示棋盘。
2. **基本阵型（6-10 回合）**：逐着说明目的，不只显示结论。
3. **逐着选择比较**：每个半回合至少给两条当前局面的真实合法变招，说明它优先完成的任务，以及推迟主线会付出的结构或发展代价。
4. **双边练习**：同一 tabiya 分别执红、执黑，避免只会背单边。
5. **脱谱题**：给一个未在主线出现但原则相同的局面。
6. **代表棋局**：只看 3 个暂停点，不要求从头背到终局。
7. **回忆测试**：次日和七日后从空棋盘复原关键阵型。

12 道概念题与每课两个红黑双边局面检查点统一保存在 `frontend/src/opening/exercises.ts`，课程正文只引用题库；现有页面负责呈现，不在内容文件里绑定新的练习 UI。

通过标准：选择题至少 80%，关键阵型连续两次复原正确，且能够用一句话解释关键着的目的。

第一版变招只依据规则合法性和开局发展原则，不标成“引擎最佳”或“必败着”。等本地 Pikafish 评分完成后，再把引擎差值和社区实战频率分别补入，不混成同一个结论。

## 从 dataset 自动生成课程材料

修复数据后，对每个 ECCO 范围执行同一套最小流程：

1. 只取从标准初始局面出发、合法回放、metadata 完整的棋局。
2. 在前 20 plies 内按规范化 FEN 合并转置。
3. 每个节点统计经过棋局数、来源数和后续 edge 频率。
4. 主线取支持度最高且教学意义明确的路径；每个节点最多保留 3 个候选着。
5. 用 ChessDB 核验常见 tabiya，用本地 Pikafish 统一计算 cp；二者结果分字段保存。
6. 将“出现频率高且损失明显”的实战着法选为错误示例。
7. 代表棋局优先选择来源明确、棋手/赛事完整、结果可信、引擎质量高的记录。

不要仅凭胜率推荐开局。胜率受棋手水平、年代、样本选择和先后手影响；课程推荐以可解释性、覆盖度和稳健性为先。

## 最小课程数据格式

第一版每课保存一个 JSON 对象即可：

```json
{
  "id": "opening-04-screen-horses",
  "title": "中炮与屏风马",
  "ecco": ["C00-C99"],
  "concepts": ["快速出车", "保护中卒", "限制马路"],
  "rootFen": "...",
  "mainline": ["h2e2", "h9g7"],
  "checkpoints": [
    { "ply": 8, "choices": ["..."], "answer": "...", "explanation": "..." }
  ],
  "sampleGameIds": ["..."],
  "sources": ["wxf-introduction-p47", "local-ecco-Cxx"]
}
```

无需为课程另建复杂 CMS。课程内容进入版本控制；大规模分支、统计和评分仍留在 dataset，通过构建脚本生成精简课程 JSON。

## 上线顺序

1. 修复 DhtmlXQ rank、和局归一化和 PGN 单局容错，重建 dataset。
2. 先制作第 1、4、10 课，验证“原则课 + 战术型开局 + 稳健型开局”三种模板。
3. 用 20-30 个 checkpoint 做内部走通，确认中文记法、转置和双边视角正确。
4. 再补齐 12 课；最后才加入个性化 repertoire 和更多冷门开局。

第一阶段完成标准不是“内容最多”，而是学习者能从原则推导出合理着法，并在真实棋谱中识别同一阵型的转置。
